# Design: Pure Rust + Tauri v2 Migration

## Status

Proposed for full implementation (2026-11-26).

Source: inline workflow input ("Migrate ccusage-gauge to pure Rust + Tauri v2 (remove Swift, native Tauri tray icon, incremental Rust JSONL usage/pricing/blocks engine)"). No GitHub issue number, Codex-agent reference, reference repository, or Cursor CLI mapping was supplied.

## Baseline Assessment

This design builds on and updates the existing specifications rather than restarting domain rules from scratch:

- `design-docs/specs/architecture.md` (updated): transitions product boundary, target boundaries, local usage data flow, menu-bar host, and asset layout from Swift/SwiftPM + local `ccusage` CLI to pure Rust + Tauri v2 while preserving configuration, mutable state, reset baseline, directory provenance, effort grouping, dashboard API, remote machine collection, and bootstrap logging contracts.
- `design-docs/specs/command.md` (updated): aligns `config-check`, `usage-snapshot`, `serve`, `dashboard`, and `client` commands with the pure Rust workspace and local native JSONL scanning.
- `design-docs/specs/client-commands.md`, `design-docs/specs/design-remote-machine-collection.md`, `design-docs/specs/design-subscription-rate-limits.md`, `design-docs/specs/design-dashboard-dark-flat-effort-grouping.md`: preserved as authoritative domain contracts re-implemented in Rust with wire and on-disk parity.
- `design-docs/specs/design-machine-session-source-directories.md`: schema-v3 registry persistence/migration, path validation and normalization, per-machine source-plan resolution, cache-fingerprint invalidation, source-generation fencing, HTTP/CLI/dashboard source editing, and the remote SSH fixed positional `ccusage` adapter contract are preserved unchanged. Its local `ccusage` subprocess execution and local multi-source command coordinator instructions are explicitly superseded by the native Rust incremental JSONL scanner running over the resolved local `MachineSessionSourcePlan` roots.
- `design-docs/tauri-dashboard.md`: superseded by the single-process Tauri v2 tray + dashboard architecture defined here (removing the Swift stdin/stdout pipe bridge and nested `CCUsageGaugeDashboard.app` helper).

## Scope and Goals

1. Remove all Swift code and SwiftPM toolchain dependencies (`Package.swift`, `Package.resolved`, `.swiftlint.yml`, `Sources/`, `Tests/`, `scripts/render-app-icon.swift`) while preserving `frontend/` intact.
2. Replace `CCUsageGaugeMenuBar` and the Swift-Tauri pipe bridge with a single-process pure Rust + Tauri v2 macOS menu-bar tray and dashboard application.
3. Replace local `ccusage` CLI subprocess invocations and local hard-link pruning mirrors with a native Rust incremental byte-offset JSONL usage scanner, USD pricing engine, and 5-hour billing block / daily / 15-minute session aggregation engine backed by SQLite `UsageAggregationCache`.
4. Maintain parity for all existing product features: Claude, Codex, and Gemini (`agy` PTY) rate limits; remote SSH `ccusage` collection; dashboard HTTP API and Tauri IPC serving `frontend/`; `ccusage-gauge` CLI subcommands; persistent bootstrap logging; and on-disk file compatibility under `~/.config/ccusage-gauge`, `~/.local/ccusage-gauge`, and `~/.cache/ccusage-gauge`.
5. Update `mise.toml`, build/test/lint/smoke/Homebrew Formula & Cask scripts, CI/emulation configs, and repository documentation for the pure Rust + Tauri v2 workspace.

## Cargo Workspace and Binary Boundaries

A single root `Cargo.toml` workspace (and single root `Cargo.lock`) organizes the codebase into three crates:

| Crate | Kind | Output | Ownership |
| --- | --- | --- | --- |
| `crates/ccusage-core` | library | rlib | Config/state/paths, bootstrap JSONL logger, incremental JSONL scanners (Claude/Codex/Antigravity), LiteLLM + fallback pricing engine, 5-hour blocks / daily / 15-min session aggregation, SQLite stores (`UsageAggregationCache`, `DashboardStateStore`, `DashboardDirectoryNameStore`), remote SSH machine registry/collector/runner, rate-limit service (Claude/Codex/Gemini PTY), dashboard query service, `MachineDashboardRouter`, loopback HTTP server (`DashboardHTTPServer`), and loopback API client (`DashboardAPIClient`). |
| `crates/ccusage-cli` | binary | `ccusage-gauge` | Headless `clap` CLI (`config-check`, `usage-snapshot`, `serve`, `dashboard`, `client ...`), text/JSON renderers, and exit-code mapping (`0, 1, 2, 3, 4, 5`). No Tauri, AppKit, or WebKit linkage so Linux amd64 builds and Docker Compose emulation containers remain lightweight and headless. |
| `src-tauri` | binary | `ccusage-gauge-app` | Single-process Tauri v2 desktop application hosting both the macOS menu-bar tray (icons, title, tooltip, native menu, settings dialogs, Launch at Login) and the embedded SolidJS `"main"` dashboard `WebviewWindow` backed in-process by `ccusage-core`. |

### Single-Process GUI and `ccusage-gauge dashboard`

- The previous two-process Swift <-> `ccusage-gauge-dashboard --swift-host` anonymous pipe bridge and the nested `Contents/Helpers/CCUsageGaugeDashboard.app` helper bundle are eliminated.
- **Tray mode (`ccusage-gauge-app`)**: Runs as a macOS menu-bar accessory app (`ActivationPolicy::Accessory`) owning the tray, `MachineCollector`, `MachineDashboardRouter`, and `RateLimitUsageService` in one process with no TCP listener. Startup honors `dashboardAutostart` from `ccusage-config.json`:
  - When `dashboardAutostart` is `true` (default), startup opens the in-process `"main"` Tauri dashboard `WebviewWindow` immediately, served via `dashboard_request` IPC.
  - When `dashboardAutostart` is `false`, startup keeps the dashboard window closed until the user requests it via `Open dashboard` / `Open dashboard window` from the tray menu.
  - Opening the dashboard creates or focuses the single `"main"` `WebviewWindow` sharing the live in-process router and collectors; closing the window hides/closes it and returns the app to accessory mode without stopping polling or quitting.
- **CLI dashboard launch (`ccusage-gauge dashboard` -> `ccusage-gauge-app --dashboard-only`)**:
  - Executable resolution preserves exact override precedence:
    1. When `CCUSAGE_GAUGE_DESKTOP_EXECUTABLE` is set in the environment (even if empty), `ccusage-gauge dashboard` validates that exact path as an executable file and uses it as the GUI binary. It never falls back to sibling discovery when an explicit override is missing or non-executable; instead it exits `1` with the existing sanitized diagnostic (`Tauri dashboard executable missing. Run mise run desktop:build, or set CCUSAGE_GAUGE_DESKTOP_EXECUTABLE.`).
    2. When `CCUSAGE_GAUGE_DESKTOP_EXECUTABLE` is unset, `ccusage-gauge dashboard` resolves the sibling `ccusage-gauge-app` executable beside the canonicalized `ccusage-gauge` binary, returning the same exit-`1` diagnostic if missing or non-executable.
  - Launching `ccusage-gauge-app --dashboard-only` starts the collector and opens one tray-free `"main"` Tauri dashboard window unconditionally (ignoring `dashboardAutostart`) backed by in-process `dashboard_request` IPC with no TCP listener. `ccusage-gauge dashboard` stays in the foreground waiting for the GUI process and exits `0` once the window closes, or terminates the child and exits cleanly on `SIGINT`/`SIGTERM`.

## Native Tauri v2 macOS Menu Bar Tray

### Status Icon Rasterization (`TrayIcon::set_icon_with_as_template`)

The status strip is rasterized in Rust as an RGBA8 pixel buffer at 2x Retina pixel density (`36px` tall = `18pt @ 2x`), using black RGB `(0, 0, 0)` with alpha carrying template opacity, and applied via `TrayIcon::set_icon_with_as_template(Some(image), true)`:

- **Layout**: For each active `MenuBarStatusEntry` in canonical `PieChartID` order (`budget`, `claude5h`, `claudeWeekly`, `codex5h`, `codexWeekly`, `gemini5h`, `geminiWeekly`), draw its `18pt x 18pt` (`36x36px`) icon (omitted for `budget` when only budget ratio text is enabled without the budget icon), optional `3pt` gap + inline ratio text (`45%`, `--`) when selected in `menuBarRatioLabels`, and `7pt` gaps between entries.
- **Provider fill logos (`Claude`, `Codex`, `Gemini`)**:
  - Embed the official Claude (`72x72` PNG) and ChatGPT/Codex (`36x36` PNG) template assets statically in Rust (`include_bytes!`).
  - Rasterize the Gemini 4-point star cubic Bezier mark at `36x36` (`(18,35)->(35,18)->(18,1)->(1,18)->(18,35)`).
  - Once at startup per provider: crop to opaque bounding box (`alpha > 5`), scale to `36x36`, compute a morphological minimum erosion mask (radius `max(1, width / 18 * 0.5)` matching `CIMorphologyMinimum`) to separate hollow `outline = solid - interior` from `interior`, and compute the bottom-to-top `cumulative_interior_by_row` CDF.
  - At render time: map usage fraction `f` clamped to `[0.0, 1.0]` through `fill_height_fraction(f)` using `cumulative_interior_by_row` (area-proportional fill so narrow star tips visibly fill at small percentages), draw `outline`, clip bottom-up to `height * fill_height_fraction`, and composite `solid`. When unavailable (`None`), draw `outline` with a diagonal slash from `(2pt, 2pt)` to `(16pt, 16pt)`.
- **Budget pie icon (`budget`)**:
  - At `36x36` with `2pt` (`4px`) inset: when `is_usage_unavailable || !collection_warnings.is_empty()`, draw the warning triangle and exclamation mark; otherwise draw a `0.35`-alpha circular rail plus a solid clockwise wedge from 12 o'clock for `visualFraction`, or a 90-degree unknown wedge when a budget is configured without snapshot data, or a vertical center bar when no budget is configured.
- **Inline ratio percentages**: Rasterized directly into the RGBA template strip using anti-aliased monospaced-digit glyphs so icon-percentage pairs align cleanly with each provider icon.
- **Anti-flicker change detection**: Cache `applied_icon_state` (rendered entries + warning state), `applied_title`, and `applied_tooltip`. Call `TrayIcon::set_icon_with_as_template`, `TrayIcon::set_title`, and `TrayIcon::set_tooltip` only when their respective input state actually changes.

## Native Rust Incremental Local Usage Engine

Local usage collection replaces local `ccusage` CLI execution and local hard-link directory mirroring completely. Remote SSH machines continue to invoke remote `ccusage` over SSH unchanged.

### Incremental Byte-Offset JSONL Scanner

All three local sources use a shared per-file `UsageEventFileScan<Context>` cache keyed by canonical file path:

- **Tracked metadata**: `file_size: u64`, `modified: Option<SystemTime>`, `scanned_through: Option<u64>` (byte offset immediately after the last complete newline-terminated line), `boundary: Vec<u8>` (up to 256 bytes ending at `scanned_through`), `since: String` (local `YYYY-MM-DD`), `timezone_id: String`, `events: HashMap<String, CachedUsageEvent>`, and per-agent `context`.
- **Step selection**:
  1. `reuse`: `timezone_id` matches, `entry.since <= requested_since`, `file_size` and `modified` are unchanged -> zero file reads.
  2. `resume`: `timezone_id` matches, `entry.since <= requested_since`, `file_size >= scanned_through`, and the file bytes `[scanned_through - boundary.len() .. scanned_through]` equal `entry.boundary` -> seek to `scanned_through`, read only newly appended complete lines using carried `context`, and advance metadata.
  3. `rescan`: file missing from cache, shrunk, modified in place (boundary mismatch), earlier `since`, or timezone changed -> scan using reverse-scan optimization for bounded `since` or forward scan when unbounded.
- **Memory policy**: Keep per-file scan caches for active refreshes covering (1) the recent rolling window `[retention_floor, today]` where `retention_floor = min(today - 8 days, initial_from - 1 day)` (where `initial_from` is the start of the current host calendar week), and (2) when the active reset cycle is `customHours(n)` with `start_day = local_day(interval.start) < retention_floor`, a bounded single-day **active-boundary scan slot** pinned strictly to `start_day` (retaining only events falling on `start_day` plus file metadata/offsets, while completed interior days strictly between `start_day` and `retention_floor` are served from `UsageAggregationCache`). Prune evicted entries whenever `retention_floor` advances, `start_day` advances, or the reset cycle changes. One-off deep historical dashboard range queries (`desired_from < retention_floor`) perform bounded-memory scans without expanding the long-lived in-memory scan cache and persist completed days to `UsageAggregationCache`.
- **Source-root selection**: Local Claude and Codex roots follow `MachineSessionSourcePlan` (`includeDefaultClaudeDir` / `CLAUDE_CONFIG_DIR` / `$HOME/.claude` + `claudeConfigDirs`; `includeDefaultCodexDir` / `CODEX_HOME` / `$HOME/.codex` + `codexSessionDirs`), canonicalized and containment-deduplicated. Missing or non-directory roots are skipped without error; disabling all sources produces an empty healthy snapshot.
- **Per-agent parsing rules**:
  - **Claude Code (`<root>/projects/**/*.jsonl`)**: pre-filter lines containing `"type":"assistant"`; decode `type == "assistant"`, `message.role == "assistant"`, ISO 8601 `timestamp`, non-empty `message.model`, `sessionId`, `requestId` (fallback `message.id`), `message.id`, opaque `cwd`, `effort` / `perTurnEffort`, and `message.usage` (`input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `cache_creation.ephemeral_5m_input_tokens`, `cache_creation.ephemeral_1h_input_tokens`). Identity is `"{session_id}\x1f{request_id}\x1f{message_id}"`, retaining the highest-timestamp entry.
  - **Codex (`<root>/sessions/**/*.jsonl`)**: pre-filter `"type":"session_meta"`, `"type":"turn_context"`, `"type":"token_count"`; maintain `CodexScanContext { session_id, model, directory, effort }` where `session_id` defaults to the file stem; extract `last_token_usage` and watermark `total_token_usage` (`"{input}:{cached}:{output}:{reasoning}:{total}"`), recording non-cached `input_tokens = max(0, last.input - last.cached)`, `output_tokens = last.output`, `cache_read_tokens = last.cached`, `cache_creation_tokens = 0`.
    - **Bounded reverse scan (`rescan` with `since`)**: Probe line 1 (up to one reverse-chunk size) for `session_meta` to seed `context.session_id` and `context.directory` before scanning backwards from `region.size`. Track two states separately during reverse traversal: (1) `pending` in-range (`day >= since`) `token_count` events awaiting their preceding `turn_context`, and (2) `newest_model` / `newest_effort` captured once from the first `turn_context` encountered while scanning backwards (the newest turn context in chronological order, preserved separately for future append-resume). Never stop or set `stop_requested` while `pending` is non-empty: when a pre-cutoff `token_count` (`day < since`) is encountered while `pending` is non-empty, continue scanning backwards—even if `newest_model` is already known from a later turn—until preceding `turn_context` lines (including those before `since`) resolve every pending in-range event with its own `(model, effort)` into `resolved`. When a `turn_context` is encountered, record `newest_model`/`newest_effort` only if unset, resolve all currently `pending` events with that `turn_context`'s `(model, effort)`, and clear `pending`. Only when `pending` is empty and a pre-cutoff record (`day < since`, or pre-decode `raw_day < scan_floor` where `scan_floor = since - 1 day` with both `pending` and `resolved` empty) sets `stop_requested` may the scan exit once `newest_model` is known. Any `session_meta` encountered updates `context.session_id`/`context.directory` and flushes `resolved`; a final flush runs at scan end, and `CodexScanContext` stores `(session_id, directory, model: newest_model, effort: newest_effort)` for forward `resume` of appended bytes. Full forward scans and bounded reverse scans must produce identical in-range identities, models, efforts, and directories, and appended events on `resume` must inherit the newest `(model, effort)` and `session_meta` directory.
  - **Antigravity (`~/.gemini/antigravity-cli/brain/<uuid>/.system_generated/logs/{transcript.jsonl,transcript_full.jsonl}`)**: prefer `transcript.jsonl`, fallback to `transcript_full.jsonl`; incrementally scan with byte-offset tracking keyed by `step_index`; decode `source == "MODEL"`, `created_at`, `model`, and token counts; split trailing effort suffix (`-xhigh`, `-high`, `-medium`, `-low`, `-max`, `-minimal`); attach workspace directory from read-only `conversation_summaries.db` (using `?immutable=1` only when no `-wal` exists, never creating sidecars).

### Rust USD Pricing Engine

All monetary math uses exact decimal arithmetic (`rust_decimal::Decimal`):

1. **LiteLLM pricing cache**: Asynchronously fetches `https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json` into `~/.cache/ccusage-gauge/litellm-pricing.json` (mode `0600`) at most once every 24 hours via an injectable HTTP transport (timeout 10s, non-blocking). Failures never abort collection; the engine uses the last valid on-disk cache if available, otherwise the compiled built-in fallback table.
2. **Built-in fallback table**: Covers current Anthropic Claude, OpenAI/Codex, and Google Gemini/Antigravity model families so offline or first-run usage computes accurate USD costs without network access.
3. **Antigravity date-effective schedule**: Retains exact `AntigravityModelPricing` rates and effective-date transitions (`gemini-4-neon`, `gemini-4-hydrogen`, `gemini-4-argon` / `gemini-4-carbon` on `2026-12-01 UTC`, `gemini-3.8-flash` on `2027-01-01 UTC`).
4. **Model resolution**: Exact normalized key -> provider-prefixed variants (`anthropic/`, `openai/`, `google/`, `gemini/`) -> stripped date/snapshot suffixes -> built-in fallback -> `$0` for unknown models (retaining token counts).
5. **Token-bucket costing**:
   - Computes `input * input_rate + output * output_rate + cache_read * cache_read_rate + cache_5m * cache_5m_rate + cache_1h * cache_1h_rate`.
   - Unclassified Claude cache-creation tokens (`max(0, cache_creation - cache_5m - cache_1h)`) are priced at the 5m rate (`1.25 * input_rate` fallback when LiteLLM omits explicit 5m rate; 1h fallback `2.0 * input_rate`; cache-read fallback `0.1 * input_rate`).
   - When LiteLLM defines above-200k tiered rates (`*_above_200k_tokens`), tokens above 200,000 in a turn use the tiered rate.

### Local 5-Hour Billing Blocks, Daily Metrics, 15-Minute Chart Buckets, Exact Rolling Totals, and Legacy Cache Compatibility

From the deduplicated, priced local events across Claude, Codex, and Antigravity:

- **15-minute chart buckets (`dashboardSessions` / `session_metrics`)**: Floor event timestamp to `floor(unix_seconds / 900) * 900`, aggregate exact decimal `costUSD` and token sums keyed by `(bucket_timestamp, agent, model, directory, effort)` with `dataQuality = "timestamped"`. These floored buckets drive `GET /api/cost-series` (`15min`/`hourly`/`6hour`), `GET /api/metrics?range=recent12h`, directory/effort-resolved daily rollups, and SQLite `session_metrics` persistence.
- **Exact rolling-window totals (`hourly` and `customHours(n)`)**: Separate chart bucketing from period-cost boundary filtering so 15-minute flooring never drops in-window events or includes expired events when a rolling boundary falls inside a bucket, while preserving append-only / zero-reread steady-state polls for arbitrarily long positive `customHours(n)` settings (e.g., `customHours(240)`):
  - Every period-cost consumer—the macOS tray (`CostSnapshot.costSinceResetUSD`, `CostSnapshot.budget`, `CostSnapshot::applying`), CLI `ccusage-gauge usage-snapshot`, and `GET /api/budget` (both unfiltered and `directory`-filtered)—evaluates the exact same half-open interval `[interval.start, interval.end)` where `interval.start == baseline.activeBoundaryAt` (`now - n hours` for `customHours(n)`, `HH:00:00` for `hourly`) and `interval.end == now` for `customHours(n)` (`HH+1:00:00` for `hourly`). An event at `timestamp == interval.start` is included; an event at `timestamp == interval.end` is excluded.
  - **Short active windows (`start_day = local_day(interval.start) >= retention_floor`)**: Exact unfloored priced local events for `[start_day, today]` are already retained in the normal in-memory `UsageEventFileScan` cache (covering restart and cross-midnight boundaries via one bounded scan on startup, then `reuse`/`resume` on subsequent polls). `CostSnapshot` retains the exact unfloored rolling-window events alongside `dashboardSessions` so tray, `usage-snapshot`, and `GET /api/budget` (unfiltered and directory-filtered) evaluate exact `interval.start <= event.timestamp < interval.end` contributions (e.g., for `[11:07, 12:07)` with `$1` at `11:06` and `$2` at `11:08`, the rolling total is `$2` while the `11:00` 15-minute chart bucket remains `$3`).
  - **Long active windows (`start_day < retention_floor`, e.g., `customHours(240)`)**: Split `[interval.start, interval.end)` into three disjoint regions without capping `n` and without re-reading unchanged old logs on steady-state polls:
    1. *Partial boundary day `start_day`*: Scanned once on cold start, restart, or when `start_day` first becomes active, and pinned in the single-day **active-boundary `UsageEventFileScan` slot** (storing only `start_day` events and file metadata/offsets). Consecutive polls hit `reuse` (zero disk reads) on unchanged old logs and `resume` (tail-only, counted once) on appended logs, supplying exact unfloored timestamps (with directory provenance) for `[interval.start, start_of_next_day(start_day))`.
    2. *Completed interior days (`start_day < d < retention_floor`)*: Every bucket on an interior day lies strictly inside `[interval.start, interval.end)`. These days are materialized once into SQLite `UsageAggregationCache` and reused directly from cached aggregates on every poll (`daily_metrics` / `session_metrics` for unfiltered totals; `session_metrics` for directory-filtered `/api/budget`) with zero raw log reads and zero extra in-memory scan cache entries.
    3. *Recent window `[retention_floor, today]`*: Served from the normal in-memory `UsageEventFileScan` cache (`reuse`/`resume`) using exact unfloored events filtered by `event.timestamp < interval.end`.
  - **Active refresh vs one-off scans and lifecycle transitions**: One-off historical dashboard range queries (`desired_from < retention_floor`) never populate the active-boundary slot. When the rolling interval moves and `local_day(interval.start)` advances to `start_day + 1`, the prior boundary-day slot is evicted and replaced by scanning only the new boundary day once (or cleared once `start_day >= retention_floor`). When the reset cycle changes, any unneeded boundary-day slot is immediately evicted or repinned to the new cycle's `start_day`. On process restart, interior days are reused from `UsageAggregationCache` while only `start_day` (if `< retention_floor`) and `[retention_floor, today]` are scanned once.
  - **Authoritative per-partition input precedence for legacy local days (`d < today`) and remote fallback**: Compatible legacy SQLite `session_metrics` rows are never rewritten. To guarantee that rolling budgets never undercount preserved legacy history and never double-count surviving logs, every historical `(local_day, agent, model)` partition—identically across both the recent window `[retention_floor, today]` and the pinned boundary day `start_day`—selects **exactly one** authoritative input using the same completeness check as legacy provenance backfill:
    - *Complete native or reconstructible legacy partition* (day populated natively, or legacy partition whose scanned local JSONL events are non-empty and match the authoritative cached `daily_metrics` integer token totals exactly): use **only** the exact unfloored raw local JSONL events (cost-conserved to authoritative daily totals when applicable), filtered by `interval.start <= event.timestamp < interval.end` and active `directory` selections.
    - *Partial, unverifiable, or absent-log legacy partition* (cached in SQLite `UsageAggregationCache` where surviving local JSONL events are absent or fail the exact token-count completeness check against cached `daily_metrics`, e.g., `$6` at `22:45` deleted while `$4` at `23:15` survives against `$10` cached): use **only** the retained SQLite `session_metrics` rows for that `(local_day, agent, model)` as the sole input—never substituting surviving partial raw events and never adding raw events on top of cached rows—filtered by the exact same half-open predicate `interval.start <= row.timestamp < interval.end` and, when directory filters are active, by their stored `row.directory`.
    - *Remote SSH machines*: continue filtering `session_metrics` by the same half-open `interval.start <= row.timestamp < interval.end` predicate.
- **Daily metrics (`dashboardMetrics` / `daily_metrics`)**: Aggregate the exact same priced events by `(local_calendar_day, agent, model)` with `directory = None` (preserving the existing unfiltered aggregate table shape while directory-filtered and `directoryBreakdown=true` / `effortBreakdown=true` queries derive identical totals from `dashboardSessions`).
- **5-hour billing blocks (`points`) — regenerative block-state reconstruction and warm-cache restart parity**:
  - Point coverage is computed **independently** of SQLite `daily_metrics` / `session_metrics` coverage because the compatible SQLite schema stores only daily and session aggregates.
  - Let `points_from = min(initial_from, desired_from)` (where `initial_from` is the start of the current host calendar week, matching `initialCoverageStart`). Because each 5-hour block opens relative to its predecessor's event-anchored `floor_to_utc_hour(event.timestamp)` start, a fixed one-day lookback cannot recover block phase across continuous usage spanning multiple days.
  - **Known block-state reconstruction (`block_context_from`)**: On restart or historical range expansion, resolve `block_context_from` by scanning backwards in expanding chunks starting from `points_from - 1 local day` across all configured local sources (Claude, Codex, Antigravity) until a **proven regenerative reset** before `start_of_day(points_from)` is reached—specifically EITHER:
    1. A gap of at least 5 hours (`e_next.timestamp - e_prev.timestamp >= 5h`) between two consecutive sorted events across all local providers where `e_prev.timestamp < start_of_day(points_from)` (making `e_next` a guaranteed fresh block opening at `floor_to_utc_hour(e_next.timestamp)` independent of all earlier events), OR
    2. A verified `>= 5h` event-free quiet interval `[t_earliest - 5h, t_earliest)` immediately preceding the earliest event `t_earliest` in the scanned prefix, OR
    3. The earliest available event across all configured local log files when no such 5-hour gap exists in prior history.
  - **Restart reconstruction, range expansion, and steady-state incremental reuse**:
    - Replay sorted deduplicated priced local events forward from that known regenerative reset (`block_context_from`) through `today`, producing identical block opening timestamps, costs, and sorted unique model sets regardless of whether the query is full-history, narrow-range, expanded-range, cold-cache, or warm-cache restart.
    - To avoid repeatedly scanning unchanged historical logs on steady-state 20-second polls, the collector retains an in-memory **`BlockAnchor`** checkpoint at `retention_floor`: (a) any completed blocks in `[points_from, retention_floor)` for the active window, (b) the exact open-block state `(block_start, last_event_timestamp, cost_usd, models)` entering `retention_floor`, and (c) for every contributing file that contains pre-`retention_floor` events, its incremental scan validation state `(canonical_path, file_size, modified, scanned_through, boundary)`.
    - **Checkpoint validity and recent-only append preservation**: On subsequent steady-state polls, validate each file tracked in `BlockAnchor` against its incremental scan step:
      1. *Unchanged (`reuse`)*: `file_size` and `modified` match -> zero disk reads; `BlockAnchor` remains valid.
      2. *Validated recent-only append (`resume`)*: For a spanning log file (containing events on both sides of `retention_floor`) whose `file_size >= scanned_through` and whose prefix boundary bytes `[scanned_through - boundary.len() .. scanned_through]` match `boundary` (confirming the historical prefix is unmodified), read only the newly appended bytes `[scanned_through .. new_scanned_through)`. If every newly decoded event in the appended tail has `local_day(event.timestamp) >= retention_floor`, **preserve `BlockAnchor` untouched** (zero historical prefix reads), advance the file's tracked `(file_size, modified, scanned_through, boundary)` in `BlockAnchor`, and replay only from `BlockAnchor` across the in-memory `UsageEventFileScan` events for `[retention_floor, today]`.
      3. *Historical change requiring reconstruction*: Rebuild `BlockAnchor` from the known regenerative reset (`block_context_from`) whenever any change can affect pre-`retention_floor` inputs—specifically: a validated append contains a backdated event with `local_day(event.timestamp) < retention_floor`; a contributing file is truncated (`file_size < scanned_through`), replaced or edited in place (boundary check fails), or removed; a newly discovered file introduces events with `local_day(event.timestamp) < retention_floor`; a deeper historical range expansion (`desired_from < cached_points_from`) is requested; the timezone changes; or the process restarts. (When `retention_floor` advances forward across midnight without historical mutation, advance `BlockAnchor` monotonically in memory from the prior anchor plus newly aged-out in-memory events without re-reading historical logs.)
  - **Grouping and cold/warm parity**: Open a new block at `floor_to_utc_hour(event.timestamp)` whenever no block is open, `event.timestamp >= block_start + 5h`, or `event.timestamp - last_event_timestamp >= 5h`; sum decimal `costUSD` and unique sorted `models` into `CCUsageCostRecord { timestamp: block_start, costUSD, models, machine: "local", directory: None }`. Retain every block overlapping `[start_of_day(points_from), end_of_day(today))` (`block_last_event_timestamp >= start_of_day(points_from) && block_start < end_of_day(today)`), preserving both cross-midnight active blocks (e.g., `22:00 UTC` yesterday combining `22:05` yesterday and `01:05` today) and continuous multi-day chains (e.g., hourly `:05` events from `points_from - 2d 23:05` through `points_from 01:05` placing `$2` at `points_from 00:00`). Cold-cache, warm-cache, restarted, narrow, and expanded queries therefore produce identical `points` for `GET /api/recent`, `GET /api/day`, and `GET /api/period`.
- **SQLite `UsageAggregationCache` persistence and legacy Swift-cache upgrade compatibility**:
  - In Swift, Antigravity (`agent == "agy"`) was appended to snapshots separately from SQLite persistence, so a valid Swift-era `aggregates-local.sqlite3` (`PRAGMA user_version <= 1`) can have both `coverage_ranges` and `directory_coverage_ranges` covering yesterday while holding only Claude and Codex rows—including cached-only rows whose original JSONL logs may since have been removed.
  - To preserve all three providers and cached-only history without destructive cache resets or changes to remote SSH cache semantics, the local cache adds one idempotently created additive table `antigravity_coverage_ranges(since_day TEXT NOT NULL, through_day TEXT NOT NULL, PRIMARY KEY(since_day, through_day))` (local cache only; remote caches remain untouched and keep unchanged `sourceConfigurationFingerprint` and `sourceGeneration` fencing, while pre-upgrade `NULL` fingerprints continue to be adopted rather than purged). Existing pre-`user_version = 1` local DBs continue to run the one-time `DELETE FROM directory_coverage_ranges` + `PRAGMA user_version = 1` migration.
  - For each completed historical day `d < today` in the requested range:
    1. **Uncovered (`d` not in `coverage_ranges`)**: Scan Claude, Codex, and Antigravity for `d`; atomically replace any rows for `d` and add `d` to `coverage_ranges`, `directory_coverage_ranges`, and `antigravity_coverage_ranges`.
    2. **Aggregate-covered, provenance-unscanned (`d` in `coverage_ranges`, not in `directory_coverage_ranges`)**: Authoritative cached Claude/Codex `daily_metrics` for `d` are **never** removed or rewritten. Evaluate each cached Claude/Codex `(agent, model)` partition on `d` against the scanned local JSONL events for `(d, agent, model)` under a strict total-conservation rule (because legacy `session_metrics` rows have no source-file identity):
       - *Complete source logs*: Replacement is permitted **only** when scanned local events for `(d, agent, model)` are non-empty and their summed integer token counts `(input_tokens, output_tokens, cache_creation_tokens, cache_read_tokens)` **exactly equal** the authoritative cached `daily_metrics` token totals (with at least one token total `> 0`, or both cached and raw costs equal to `0`). Only in this complete-coverage case does the backfill replace that `(d, agent, model)` `session_metrics` partition with directory- and effort-attributed 15-minute buckets whose summed `costUSD` and all four token totals exactly equal the authoritative `daily_metrics` row (allocating authoritative `costUSD` across the complete event set with remainder on the final event).
       - *Partial or unverifiable source logs* (e.g., 1 of 2 contributing logs survives, reconstructing `$4` against `$10` cached daily/session totals, or token totals do not match): **Conservative fallback**—retain the existing valid cached `session_metrics` rows for `(d, agent, model)` completely untouched alongside the authoritative `daily_metrics` row. Never replace cached rows with a partial rescan, never insert partial rows additively alongside cached rows, and never scale missing usage onto surviving directories.
       - *Absent source logs* (0 surviving events for `(d, agent, model)`): **Conservative fallback**—retain the existing valid cached `daily_metrics` and `session_metrics` rows untouched as cached-only unattributed history.
       - Simultaneously, if `d` is absent from `antigravity_coverage_ranges`, scan Antigravity transcripts for `d` and replace any prior `agent == "agy"` rows in `daily_metrics` and `session_metrics` for `d`. Commit all partition updates together with adding `d` to `directory_coverage_ranges` and `antigravity_coverage_ranges` in one `BEGIN IMMEDIATE ... COMMIT` transaction.
    3. **Legacy-covered (`d` in `coverage_ranges` and `directory_coverage_ranges`, not in `antigravity_coverage_ranges`)**: Treat cached Claude and Codex `daily_metrics` and `session_metrics` as complete and **do not delete or rebuild them** (preserving cached-only Claude/Codex history whose logs are gone). Scan only Antigravity transcripts for `d`, atomically delete any prior `agent == "agy"` rows in `daily_metrics` and `session_metrics` for `d`, insert the freshly scanned `agent == "agy"` rows, and add `d` to `antigravity_coverage_ranges` inside one `BEGIN IMMEDIATE ... COMMIT` transaction.
    4. **Native-complete (`d` in `coverage_ranges`, `directory_coverage_ranges`, and `antigravity_coverage_ranges`)**: Reuse all cached Claude, Codex, and Antigravity rows directly without re-scanning historical logs for aggregate writes.
    5. **Current local day (`d == today`)**: Never persisted to historical coverage; always scanned incrementally across all three providers and merged in memory with cached historical days.
  - **Atomicity, publication, and retry**: Every historical write or backfill runs inside one SQLite `BEGIN IMMEDIATE ... COMMIT` transaction guarded by the `sourceConfigurationFingerprint` + `sourceGeneration` fence, and snapshots are published only after commit. On failure or interruption, SQLite rolls back both rows and coverage markers, retains the previously published snapshot, and retries cleanly via deterministic partition-level evaluation and full-partition replacement (for complete provenance partitions or `agent == "agy"`) rather than additive insertion—preventing Antigravity duplication, preventing silent total loss on partial logs, and guaranteeing identical daily and session totals across reopens and retries.
